# Fork-Based Codex MVP

## Summary

Prototype native Codex support in a personal fork, validate it locally with
disposable profiles, run an independent review, then submit one focused
upstream PR.

Keep the first contribution intentionally narrow. Defer hooks, PowerShell
Codex support, Homebrew changes, and plugin packaging until the core workflow
is accepted.

## Public Interface

Add:

```bash
./install.sh --target codex
./install.sh --uninstall --target codex
```

The existing default remains Claude Code. Codex users invoke `$distill`.
Codex knowledge is stored separately under `$CODEX_HOME/distill/`, defaulting
to `~/.codex/distill/`.

Codex built-in Memories remain untouched. When Codex Memories and aura-distill
overlap, curated aura-distill guidance wins.

## Implementation

1. Add Codex-specific skill, process, and monitor templates.
2. Extend `install.sh` with an opt-in Codex target and knowledge-preserving
   uninstall.
3. Add isolated Bash tests using temporary `HOME` and `CODEX_HOME`.
4. Document installation, coexistence with Codex Memories, and deferred work.

## Test Plan

- Verify fresh Codex installation creates the skill, process, monitor, SPINE,
  version file, tier directories, and managed global `AGENTS.md` block.
- Verify reinstall is idempotent and preserves existing AGENTS content,
  SPINE entries, Codex config, and Codex Memories.
- Verify Codex uninstall removes installed integration assets while preserving
  SPINE and tier knowledge.
- Run existing Claude Code installer tests to catch regressions.
- Run a disposable `codex exec` smoke test when local authentication permits.

## Git Workflow

1. Develop on `feature/codex-support`.
2. Push only to a personal fork.
3. Open a draft fork PR for validation.
4. Run the independent review in `REVIEW-PROTOCOL.md`.
5. Submit one upstream PR after tests and review pass.
